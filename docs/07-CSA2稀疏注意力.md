# 第 07 课：CSA2——压缩、稀疏、SWA、跨层共享

> `V4Attention` 可能是全仓库最复杂的类：MLA、压缩 KV、稀疏索引、滑窗、YoCo、跨层共享、打包 KV 全在一个 forward 里。
> 本课按"配置 → 分支 → kernel"三层拆开。

## 本课目标

1. 说出 `V4Attention` 支持的 6 种机制的配置开关。
2. 理解 CSA2 的三种层模式（Full / Reindex / Reuse）与代码里的 `is_kv_source` / `is_index_source` 的对应。
3. 能解释稀疏索引器如何用 `relu(q@k)*w` 选 top-k 块，以及"分层索引"如何限制深层成本。
4. 知道组合约束（哪些配置不合法），避免改配置时踩坑。

## 配置面：一个 attention 层的 7 个开关

来自 `ModelMetadata`（`model_metadata_utils.py`）与 `V4AttentionBase`：

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `kv_compress_ratio` | 0 / 1 / 2 | KV 压缩率（C1/C2；C4/C128 已删） |
| `index_topk` | 0 / >0 | 稀疏索引每 query 选多少 token/块；0 = dense |
| `use_swa` | bool | 是否叠加滑窗注意力 |
| `n_packed_heads` | 0 / >0 | 打包 KV 的头数（跨层共享 KV） |
| `attn_index` | 配置 | indexer 的头数/维度/kproj |
| `o_groups` | int | 输出投影的分组数 |
| `use_fp4_sparse_kv` | bool | 主 KV 是否 FP4 |

类里的派生：

```python
self.is_sparse = bool(self.layer_cfg.get("index_topk"))
self.use_swa = self.layer_cfg.get("use_swa", True)
self.has_packed_kv = self.layer_cfg.get("n_packed_heads", 0) > 0
assert self.use_swa or self.has_packed_kv, "use_swa=False requires packed KV attention"
if self.is_sparse:
    assert self.use_swa
```

两条硬约束：
- 不开 SWA，就必须有 packed KV（否则没有局部上下文）；
- 开稀疏，必须开 SWA（稀疏选全局块 + SWA 补局部）。

## 三种层模式（CSA2 的外部命名）

官方/第三方资料把 CSA2 的层分成三种静态模式：

| 模式 | 作用 | 代码线索 |
| --- | --- | --- |
| **Full** | 自己算 main KV + indexer K，产出 top-k 索引 | `is_kv_source`、`has_local_index` |
| **Reindex** | 复用 main KV，但自己重算 indexer K / top-k | `is_index_source` |
| **Reuse** | 直接复用上一层的 top-k 索引 | `SharedLayerTopology` 的共享关系 |

代码里没有 `mode="Full"` 这种字符串，而是用 `SharedLayerTopology` 表达"哪层是 KV source、哪层共享谁的 KV/index"。`cross_layer.py` 的 `build_shared_layer_topology()` 负责构建。

为什么要共享：MLA 的 KV 投影是每层独立的，如果每层都存一份完整 KV，显存和带宽都吃不消；共享后，后面几十层只读同一份 main KV，只额外维护很小的 indexer K。

## 稀疏索引器：MQA

`v4_modules/index_attn.py` 的类注释：

```
The indexer of sparse attention: computes the relu(q@k)·weights logits
and selects the topk compressed kv for each query
```

流程：

```
压缩后的 KV（compressed latent）
   │
   ├─ KProject：linear + RMSNorm → index-K（pre-RoPE）
   │      └─ 存进 index KV cache（FP4，per-32）
   │
   └─ 每个 query：
        logits = relu(q @ k) * weights     # 单头 MQA，不是多头 softmax
        topk(logits) → 选中的块/ token 索引
```

为什么用 `relu(q@k)*w` 而不是 softmax：
- 只是为了**打分选块**，不需要归一化；
- 单头（MQA）成本低；
- top-k 可以用 `deep_select.interface.topk` 这种专用 kernel。

选完块之后，真正的 attention 只在选中的块上算（`decode_mla_mqa_sparse` / `prefill_attn_varlen_sparse`），SWA 的局部结果再拼进来。

## 分层稀疏索引（Hierarchical Sparse Indexer）

外部资料的说法：decoder 后段的索引层不再对全上下文打分，而是只在**第一个 Full 层给出的候选池**里选。

代码线索：
- `candidate_blocks.py`：`candidate_block_max`、`get_candidate_compact_lens`、`restore_candidate_indices_inplace`；
- `index_attn.py` 里维护 `candidate_mqa_lens`、`candidate_mqa_schedule_metadata`；
- `cross_layer_runtime.candidate_*` 在 YoCo compact 边界会被清空重建。

收益：深层索引成本与上下文长度**解耦**（只看候选池），否则 100 层 × 128k 上下文的索引打分本身就很贵。

## 压缩 KV：C1 / C2

`v4_modules/compress.py` 的注释：

```
Compressed-KV runtime: gated low-rank compression, norm and KV-cache update.
`Compressor` returns the pre-RoPE compressed KV that feeds the sparse indexer and stores the
post-RoPE values in the main KV cache. `KProject` projects that pre-RoPE latent to index-K.
```

- `kv_compress_ratio` 取 1 或 2（C1/C2）：表示压缩窗口的大小；
- 压缩是 gated low-rank：先降维，再过 gate，再升维；
- 压缩后的 KV 同时喂给 indexer（pre-RoPE）和主 cache（post-RoPE）。

`ModelMetadata` 的约束：

```python
if not set(self.kv_compress_ratio_list) <= {0, 1, 2}:
    raise ValueError("Only C1/C2 compression is supported; C4 and C128 have been removed")
if any(attn.cfg.get("compress_overlap", False)):
    raise ValueError("Compression overlap is no longer supported")
if any(self.kv_compress_ratio_list) and cfg.get("use_ape", True):
    raise ValueError("Compression APE is no longer supported; use an APE-free checkpoint")
```

解释：C4/C128 被删了（可能效果/复杂度不划算）；compression overlap 和 APE 也不用了，所以**老 checkpoint 可能加载不了**。

## 一个 forward 里的分支

`V4Attention.forward` 大致按这个顺序走（函数名来自代码）：

1. `_project_q_and_swa(hidden_states, shared_hidden_bf16)`：
   - 默认把 `Wq.A` 和 `Wkv.A` 融合成一个 `ReplicatedLinear`；
   - 如果 `yoco_swa_share_hidden`，kv_swa 从 **shared hidden** 投影（不是当前层 hidden），所以不能融合。
2. `_prepare_swa_kv(...)`：
   - prefill：norm + RoPE + FP4/FP8 cast + store 到 swa cache；
   - decode：读 cache + 更新 ring。
3. 压缩路径：`Compressor` 更新 main KV / compressed state。
4. 索引路径：`MQA` 打分 → top-k → 候选块。
5. attention：
   - prefill → `prefill_attn_varlen_sparse`（FlashMLA varlen）；
   - decode → `decode_mla_mqa_sparse`（FlashMLA decode）。
6. 输出投影（`o_groups` 分组）。

`sched_meta_key` 把配置编码成 key：

```python
self.sched_meta_key = f"{self.kv_compress_ratio}_{self.has_packed_kv}_{self.use_swa}_{self.index_topk}"
```

调度 metadata 按这个 key 缓存/共享——相同配置的层复用同一份调度信息，减少每步构造开销。

## kernel 地图

| 功能 | CUDA | Ascend |
| --- | --- | --- |
| norm+rope+hadamard+cast+store | `fused_transform.py` | `asc/fused_transform.py` |
| 压缩状态更新 | `compress.py` | `asc/compress.py` |
| 候选块 | `candidate_blocks.py` | `asc/candidate_blocks.py` |
| SWA 索引 | `swa_index.py` | `asc/swa_index.py` |
| KV 加载/存储 | `load_paged_kv_cache.py` / `store_kv_cache.py` | 同名 |
| top-k 选块 | `deep_select`（vendor） | `npu_ops/deep_select.py` |
| MLA attention | `flash_mla`（vendor） | `flash_mla` Ascend 版 |

一个值得注意的融合：`fused_norm_rope_hadamard_cast_store_kvcache` —— 一个 kernel 里做 RMSNorm、RoPE、Hadamard 变换、量化 cast、写 KV cache。这是为了减少 HBM 往返：中间结果不落地。

## 图解：一层 attention 的数据流

```
hidden_states ──┬─► Wq.A ─► q_a ─┬─► q_nope / q_pe（RoPE）
                │                 │
                └─► Wkv.A ─► kv ──┼─► Compressor ─► main KV（FP4）
                                    │        │
                                    │        └─► KProject ─► index-K（FP4）
                                    │
                                    └─► kv_swa ─► SWA cache（MXFP8）

q ─► MQA indexer ─► top-k blocks ─┐
q ─► SWA（局部窗口）───────────────┼─► 合并 → attention → o_proj
q ─► 选中的 main KV ──────────────┘
```

## 组合约束速查

| 约束 | 来源 |
| --- | --- |
| 只支持 C1/C2 | `ModelMetadata` |
| 不支持 compression overlap / APE | `ModelMetadata` |
| 稀疏必须配 SWA | `V4AttentionBase` |
| 不开 SWA 必须有 packed KV | `V4AttentionBase` |
| indexer 头数必须全局唯一 | `assert len(heads) <= 1` |
| Engram 层必须在 encoder 半区（compact 下） | `DeepseekModel._init_yoco` |
| DFlash target 层不能跨 encoder/decoder 边界（compact 下） | 同上 |

最后两条很重要：**YoCo 截断会限制其他特性的位置**。改模型配置时，先看 `_init_yoco` 的断言。

## 设计取舍

| 选择 | 收益 | 代价 |
| --- | --- | --- |
| 压缩 KV（C2） | KV 显存/带宽减半 | 精度损失、实现复杂 |
| 稀疏 top-k | 长上下文 attention 成本大降 | 索引器本身有成本、召回有损 |
| SWA 叠加 | 局部精度兜底 | 多一套 cache |
| 跨层共享 | 显存/带宽再降 | 层间耦合、调度 metadata 要共享 |
| 全部塞一个类 | 复用投影/norm | 可读性差、分支多 |

## 易错点

1. **以为 `index_topk` 是 token 数**：代码里按压缩块/候选池组织，不完全是原始 token。
2. **以为压缩率可以随便设**：只允许 0/1/2，且要求 APE-free checkpoint。
3. **以为所有层都存 KV**：Reuse 层不存，只读。
4. **改了 `use_swa` 但没配 packed KV**：启动断言直接挂。
5. **在 compact 模式下把 Engram 放到 consumer 层**：断言挂。
