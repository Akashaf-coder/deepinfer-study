# 导读：DeepInfer 学习地图

> 用 5.5 万行 Python + 5.9 千行 C++，看懂 DeepSeek 生产推理框架如何为**一个模型**做极致特化。
> 本系列共 15 课，风格对齐 `learn-nano-vllm`：每课都有目标、概念、源码、图解、自测。

## 本课目标

读完导读，你应该能够：

1. 用三句话说清 DeepInfer 的定位：**谁的、干什么的、开源了什么**。
2. 画出 15 节课的知识地图，并按自己的目标（读源码 / 做实验 / 准备面试）选择路线。
3. 说清它与 nano-vllm、vLLM 的关系：**同一个思想谱系，不同的优化目标**。
4. 建立"读 5 万行"的方法论：三遍读法 + 数据流优先 + 用测试当文档。

## 为什么值得读：三个不同的学习样本

| 项目 | 规模 | 学习价值 | 适合谁 |
| --- | ---: | --- | --- |
| nano-vllm | ~1,200 行 Python | 主干清晰，能一周读完，适合建立**推理引擎心智模型** | 入门、面试 |
| vLLM | 数十万行 | 通用框架的**抽象设计**与生态 | 做平台、做二次开发 |
| **DeepInfer** | 5.5 万行 Python + 5.9 千行 C++ | **单模型极致特化**：C++ 调度、异步流水线、模型-引擎协同 | 已有基础、想深入性能 |

一句话：**nano-vllm 教你"引擎长什么样"，DeepInfer 教你"为了快 10% 可以做到多狠"**。

## DeepInfer 是什么（三句话版）

1. 它是 DeepSeek 支撑 V4.1-Flash 大规模在线服务的推理框架，2026-10 开源，Apache-2.0。
2. 开源版只包含**离线推理**：一个 `LLM` 类、一个 C++ 调度器、一套 V4 模型实现、两套硬件后端。
3. 它把"大规模"里最值钱的部分（KV 存储、四类负载均衡、扩缩容、在线 API）**留在了公司内部**，所以你要读的是"引擎"，不是"系统"。

## 三个必须先接受的边界

1. **只支持 DeepSeek-V4.1-Flash**。换模型不是改配置，是重写模型 + kernel。
2. **只支持 SM100 / Ascend 950**。H100/A100 会在 `get_bf16_tflops_limit()` 直接抛错。
3. **没有在线服务**。没有 OpenAI API server，没有 `AsyncLLMEngine`；你要自己写 entrypoint。

如果你需要"部署任意模型 + OpenAI API"，请直接用 vLLM/SGLang；读这个项目的目的是**学设计**，不是选型。

## 心智模型：三层 + 两条流

```
┌─────────────────────────────────────────────────────────┐
│ 用户层    LLM.generate()  →  tokenize  →  add_request    │
├─────────────────────────────────────────────────────────┤
│ 引擎层    LLMEngine.step()                               │
│           ├─ C++ Scheduler：选 batch、算 chunk、管 block  │
│           ├─ Worker：forward → sample → post-process      │
│           └─ 输出：uint64 指针数组 + 对象池                │
├─────────────────────────────────────────────────────────┤
│ 执行层    ModelRunner → DeepseekModel → TileLang kernels  │
│           CacheEngine：paged block + state slot           │
└─────────────────────────────────────────────────────────┘

两条流：
  控制流（CPU）：schedule → launch → post-process
  数据流（GPU）：hidden states → KV cache → logits → token
```

理解这个项目的大部分难点，都来自**控制流和数据流不同步**：ZOS 让 CPU 提前一步调度，而 GPU 的结果还没回来；DSpark 用滞后的 confidence 估计下一步的验证长度。第 04、09 课会反复回到这一点。
