## 五个结构性差异

### 1. 调度器语言：C++ vs Python

- vLLM V1：Python 调度器，追求"统一、可扩展、near-zero CPU overhead"；
- DeepInfer：C++ 调度器，追求"decode 小 step 下零 Python 开销"。

判断：只有模型固定、流量巨大、值得为每微秒优化的团队才该学这招。通用框架选 Python 是对的。

### 2. 前缀缓存：引擎内 vs 引擎外

- vLLM/SGLang：引擎内自动复用（block hash / radix tree）；
- DeepInfer：引擎外（3FS + Entrypoint），引擎只接收 `hit_tokens`。

判断：这是"单机引擎"与"数据中心系统"的分野。DeepInfer 的设计让任意 prefill 机器都能命中任意前缀，代价是引入一整套外部组件（未开源）。

### 3. 并行：EP 优先 vs TP 优先

- vLLM/SGLang 默认心智：TP 切模型（单机 8 卡）；
- DeepInfer：EP64–128，全仓库无 TP。

判断：MoE + 超大 EP 是 DeepSeek 的路线。Dense 模型上这套不成立。

### 4. 投机：固定长度 vs 边际收益分配

- 主流：固定 draft 长度，验证成本固定；
- DSpark：confidence head + 变长验证，按期望吞吐选前缀。

判断：这是"算法-系统协同"的典范，单看框架代码看不懂，必须结合模型结构。

### 5. 工程形态：一个模型 × 两套硬件 × 三种引擎 × 零在线服务

- vLLM/SGLang：一个引擎适配 N 个模型；
- DeepInfer：一个模型榨干 N 种硬件。

判断：前者复杂度在抽象层，后者复杂度在 kernel 和调度细节。

## 20 道自测题（附一句话答案）

1. 三种引擎类型？→ NORMAL/PROMPT/COMPLETION，PD 分离用后两者。
2. COMPLETION 为什么必须 `stop_preempted_request=true`？→ 没有 prefill 通道，无法重算。
3. `prompt_limit` 两态？→ chunked 时 `max_model_len`，否则 `min(max_model_len, max_num_batched_tokens)`。
4. ALL/ANY 投票各防什么？→ 陪跑 / 饿死。
5. 为什么需要第二轮 allreduce？→ 防止全组空手导致 decode_step 清零死循环。
6. decode 为什么必须清空 running？→ `TORCH_CHECK(l==r)`，不允许留一部分。
7. ZOS 四段顺序？→ forward(N) → post(N-1) → sample(N) → post(N) 延后。
8. `DeferredRelease` 防什么？→ 调用方没读完就释放。
9. placeholder step 干什么？→ 空 rank 保持步型一致，防 NCCL 挂起。
10. ZOS 下 `seqlens_q` 为什么是估计值？→ 调度先于 sample，拿不到真实接受率。
11. 为什么两套缓存？→ 生命周期、介质、命中策略不同。
12. 引擎内有前缀缓存吗？→ 没有，只有 fork/COW；跨请求靠外部 KV store。
13. `hit_tokens` 与 `num_tokens` 区别？→ 前者是"应该命中"，后者是"显存里真有"。
14. YoCo 的 `n_prefill_layer`？→ encoder 层数，之后是 consumer。
15. mask vs compact？→ 只改可见域 vs 真 gather 成短 batch。
16. 为什么重放 128？→ SWA 窗口 + 6 回溯，成本常数化。
17. CSA2 三种层模式？→ Full/Reindex/Reuse，共享 KV 或 index。
18. EPLB 为什么向上取整？→ 物理专家数必须被 ep_size 整除。
19. DSpark 为什么用 N-2 选 batch、N-1 分配长度？→ confidence 滞后，总量错误代价更大。
20. batch-invariant 与 deterministic？→ 前者跨 batch 组成一致，后者端到端可复现（还要关 varlen + 固定 seed）。

## 面试/汇报的 30 秒版本

> DeepInfer 是 DeepSeek 把 vLLM 拆了重装的产物：调度器换成 C++，引擎按 P/D 拆成三种形态，KV 缓存分成 paged block 和 state slot 两套，前缀缓存推到 3FS 外部存储，并行只做 EP/DP 不做 TP，投机解码用 confidence head 做变长验证，prefill 用 YoCo 只算 encoder 层 + 重放 128 token。它只支持 V4.1-Flash 和 SM100/Ascend 950，没有在线 server，开源的是"引擎"不是"系统"。学习价值在于看它如何为单一模型做极致特化。
